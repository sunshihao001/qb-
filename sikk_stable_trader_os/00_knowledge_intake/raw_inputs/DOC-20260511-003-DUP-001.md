````markdown
本文件是 SIKK Stable Trader OS 的系统方法论总纲。

它不是交易策略文档。

## 1. 系统总定位

SIKK Stable Trader OS 不是“寻找交易机会”的系统。

它是一个由 HER 调度的结构化交易研究操作系统，用于把大量看似机会的 token 样本，通过事实校验、场景识别、钱包结构、筹码控制、策略门禁、风险否定、纸面验证、复盘归因和规则升级，逐层过滤、审计、验证和沉淀。

系统目标不是多买，而是少犯错。

系统目标不是让 AI 直接判断买卖，而是让 AI 在受控系统中执行可验证、可追溯、可复盘的判断链条。

---

## 2. 系统本质

SIKK Stable Trader OS 的本质是：

```text
筹码控制权状态机
+ 结构行为解释系统
+ 多阶段硬否定过滤系统
+ 策略门禁裁决系统
+ 风险控制系统
+ 纸面交易验证系统
+ 复盘归因系统
+ 规则升级审计系统
````

系统核心不是预测涨跌，而是控制判断流程。

系统核心不是识别“庄家”，而是基于可观察证据推断：

```text
结构侧是否存在
结构侧是否仍掌握筹码
筹码是否正在迁移
派发是否已经开始
对手盘压力是否增强
当前参与是否会变成退出流动性
策略门禁是否允许进入纸面验证
风险层是否必须阻断
```

## 3. 系统建设的根本原则

### 3.1 先方法论，后目录

不得直接从目录结构开始设计系统。

必须先明确：

```text
系统控制对象是什么
系统输入是什么
系统状态是什么
系统决策是什么
系统风险是什么
系统反馈是什么
HER 在系统中负责什么
哪些判断允许自动化
哪些判断必须被约束
哪些输出允许进入下游
```

---

### 3.2 先领域对象，后阶段

阶段只是流程。  
领域对象才是系统处理的真实对象。

必须先定义：

```text
Token
Wallet
AddressGroup
TransactionEvent
MarketScene
ChipState
DominantSide
Counterparty
GateDecision
RiskEvent
PaperPosition
ReviewCase
RuleChange
```

再定义 P00-P09 如何处理这些对象。

---

### 3.3 先事实，后推理

任何推理必须依赖事实字段。

禁止：

```text
用 AI 解释补全事实字段
用主观语言替代字段来源
用 report 文字替代机器字段
用缺失字段支撑判断结论
用未注册字段进入下游阶段
```

允许：

```text
标记字段缺失
标记证据不足
标记阶段暂停
标记阶段拒绝
标记反证存在
标记 hard negative 命中
```

---

### 3.4 先控制，后执行

系统必须先判断：

```text
是否允许进入下一阶段
是否存在阻断缺口
是否命中硬否定
是否满足证据等级
是否通过风险层
```

然后才能进入执行动作。

执行层不得越权。

---

### 3.5 先验证，后交接

每个阶段必须有对应验证机制。

没有验证机制的设计，不能进入正式系统。  
没有 handoff_packet 的阶段，不能进入下游。  
没有 replay 的判断，只能作为研究假设。

---

### 3.6 先复盘，后升级

复盘结果不能直接污染实时规则。

P08 只能输出归因。  
P09 只能输出升级提案。  
核心规则变更必须有版本记录、审计记录和生效边界。

## 4.1 控制论模型

### 4.1.1 模型定义

```text

  ↓

  ↓
控制判断
  ↓
风险约束
  ↓
输出动作
  ↓
反馈校准
```

### 4.1.2 映射到 SIKK

```text
候选 token
  ↓
事实层校验
  ↓
市场场景识别
  ↓
钱包结构判断
  ↓
筹码控制判断
  ↓
策略门禁
  ↓
风险否定
  ↓
纸面执行 / 人工确认
  ↓
复盘归因
  ↓
规则升级
```

### 4.1.3 系统设计要求

每个阶段都必须被设计为控制节点。

每个控制节点必须回答：

```text
输入是什么
状态是什么
判断是什么
风险是什么
输出是什么
是否允许进入下一阶段
```

## 4.2 OODA 模型

### 4.2.1 模型定义

```text
Observe 观察
Orient 定向
Decide 决策
Act 行动
Feedback 反馈
```

### 4.2.2 阶段映射

|OODA 环节|SIKK 阶段|作用|
|---|---|---|
|Observe|P01 数据事实层|收集与校验事实|
|Orient|P02-P04|识别场景、钱包结构、筹码状态|
|Decide|P05-P06|策略门禁与风险裁决|
|Act|P07|纸面执行 / 人工确认|
|Feedback|P08-P09|复盘归因 / 规则升级|

### 4.2.3 核心约束

```text
P01-P04 不负责买入结论。
P05-P06 才负责是否允许进入纸面验证或人工确认。
P07 不允许绕过 P05/P06。
P08/P09 不允许直接修改实时判断规则。
```

## 4.4 STAMP / STPA 控制失效模型

### 4.4.1 模型定义

系统不只关心结果错误，还要关心控制失效。

错误交易通常不是单一判断失败，而是多个控制节点连续放行造成的。

### 4.4.2 典型控制失效

|控制失效|后果|
|---|---|
|P01 字段缺失但仍进入 P02|场景识别失真|
|P03 钱包证据弱但仍进入 P04|筹码控制误判|
|P04 已主动派发但 P05 放行|成为退出流动性|
|P06 风险拒绝但 P07 执行|执行层越权|
|P08 复盘结论直接改实时规则|规则污染|

### 4.4.3 每个阶段必须回答

```text
本阶段错误放行会造成什么损害？
本阶段必须拦截哪些错误？
哪些错误必须硬否定？
哪些错误只能标记为证据不足？
哪些错误允许带 gap 进入下游？
```

## 4.5 数据血缘模型

### 4.5.1 模型定义

任何判断都必须追溯字段来源。

不得只输出：

```text
这是结构钱包
主导侧还没出货
```

```text
判断是什么
依据字段是什么
字段来源是什么
证据等级是什么
反证是什么
失效条件是什么
下游是否可用
```

### 4.5.2 标准证据链结构

```json
{
  "decision": "WALLET_SUPPORT",

    "buy_time_delta",
    "funding_source",
    "holding_duration",
    "realized_pnl",
    "sell_sync_score",
    "same_source_group_id",
    "current_position_ratio"
  ],
  "evidence_level": "EVIDENCE_B_MEDIUM",
  "counter_evidence": [
    "partial_sell_detected",
    "counterparty_pressure_rising"
  ],

    "same_source_group_sync_exit = true",
    "early_wallet_remaining_ratio < threshold"
  ]
}
```

# 10. 硬否定规则体系

硬否定高于所有解释。

一旦硬否定命中，不允许用“但是、可能、也许、这次特殊”继续放行。

## 10.1 全局硬否定

```text
字段来源不明
关键时间戳缺失
token 主键缺失
wallet 主键缺失
schema 校验失败
contract 校验失败
report 与 JSON 输出冲突
AI 推测补全事实字段
无 handoff_packet 进入下游
未检查反证直接通过
硬否定命中但仍输出 READY
```

## 10.2 交易判断硬否定

```text
安全扫描失败
报价源严重偏差
流动性不足
滑点不可控
早期结构钱包同步退出
主动派发明确
接盘鲸鱼压力过高
筹码控制权崩塌
P01 事实字段不足
P05 策略证据不足
P06 风险控制拒绝
```

## 10.3 执行层硬否定

```text
未通过 P05 策略门禁
未通过 P06 风险控制
未生成 execution_ticket
未记录模拟成交价
未定义止损 / 失效条件
触发连续失败熔断
触发当日最大亏损限制
```

# 12. HER 执行协议

HER 每次执行必须遵守以下顺序：

```text
1. 读取治理平面
   - 当前允许做什么
   - 当前禁止做什么

2. 读取运行状态
   - 当前 active_phase
   - blocking_gap
   - completed_phases
   - next_action

3. 读取控制平面
   - 阶段顺序
   - 阶段输入输出
   - 下一阶段条件

4. 读取领域平面
   - 当前处理对象
   - 字段定义
   - 状态定义

5. 读取数据平面
   - 输入文件
   - 字段来源
   - 数据质量

6. 读取风险平面
   - 是否命中硬否定
   - 是否必须暂停 / 拒绝

7. 读取决策平面
   - 当前阶段判断规则
   - 证据 / 反证 / 置信度 / 失效条件

8. 执行阶段任务
   - 调用 Atomic Skill
   - 调用工具
   - 写 runtime log

9. 读取验证平面
   - schema 校验
   - contract 校验
   - acceptance gate

10. 写入交接
   - handoff packet
   - phase state
   - current system state

11. 进入学习平面
   - 复盘
   - 归因
   - 规则升级提案
```

## 12.1 HER 禁止行为

```text
不读状态直接执行
不读阶段边界直接推理
不查硬否定直接放行
无 handoff 进入下游
用 report 代替机器状态
用 AI 推测补全事实字段
复盘结论直接修改实时规则
```
