# Wallet-Intel Harness V2.0 Control Policy

## 1. 定位
Wallet-Intel Harness V2.0 是 Hermes/HER 针对钱包数据采集分析、钱包结构分析、旧目录导入、数据语义整合的系统级控制面。

它不是普通目录整理规则，也不是临时 prompt。它是后续 Wallet-Intel 任务的自动识别、自动路由、固定工作流、验证、恢复、记忆候选化的运行协议。

## 2. 总原则
```text
System First, Model Second。
Prompt 是控制面，不是临时说明。
钱包数据整合不能按普通目录整理处理。
数据必须按语义分层，而不是按旧目录名分类。
完成标准是 Hermes 能按 token 理解数据，而不是文件复制完成。
```

## 3. 自动路由触发条件
当用户请求包含以下任一意图时，Hermes 必须路由到 Wallet-Intel 语义整合 workflow，而不是普通目录治理：

- 钱包数据采集分析
- 钱包结构分析
- Wallet-Intel
- source wallet / source_wallet_bot
- 旧目录导入 / legacy wallet data import
- 钱包数据标准化
- 数据护照
- 字段字典
- handoff 包
- 同源证据 / 结构证据
- 事实层 / 证据层 / 推断层 / 结论层 / 交接层
- 按 token 理解数据
- 导入后验证

路由名称：`wallet_intel_semantic_integration`。

## 4. Wallet-Intel 语义分层
Wallet-Intel 任务必须按语义层处理数据，不得按旧目录名直接分类。

标准层级：

```text
0. ingest：采集层 / 原始输入层
1. facts：事实层
2. evidence：证据层
3. inference：推断层
4. conclusion：结论层
5. handoff：交接层
6. reports：报告层
7. index：索引与追溯层
```

最低强制隔离：

```text
事实层、证据层、推断层、交接层必须分开。
```

推荐完整隔离：

```text
事实层、证据层、推断层、结论层、交接层、索引层全部分开。
```

## 5. 事实层规则
事实层只回答：

```text
发生了什么？
哪个钱包？
什么时候？
买了多少？
卖了多少？
还剩多少？
资金从哪里来？
是否进入 Top Holder？
是否发生 Token 转入 / 转出？
```

事实层可以直接引用，但不得包含角色判断。

禁止在事实层写：

```text
庄家、确定庄家、操盘钱包、内幕、同伙、确定同源、确认控盘、确认派发、聪明钱结论、疑似执行组、疑似控筹、疑似派发、疑似二次拉升。
```

## 6. 证据层规则
证据层保存可支持推断的证据，不等于结论。

证据类型包括：

- 同源候选证据
- 资金路径证据
- Token 转入 / 转出证据
- Top Holder 变化证据
- 钱包行为同步证据
- GMGN 标签证据
- K线阶段证据
- 旧路径来源证据
- raw_unit_refs / source_path / checksum 追溯证据

证据层必须能回指事实层和原始来源。

## 7. 推断层规则
推断层回答：

```text
这些钱包是否同源？
是否疑似执行组？
是否疑似控筹？
是否正在派发？
是否有二次拉升动机？
是否应该支持 / 暂停 / 阻断？
```

推断层必须带：

```text
证据等级
引用事实
引用证据
主要依据
不确定点
反向证据
下一步补查
```

推断层不能被下一轮系统当作事实直接继承。上一轮推断只能作为 `historical_inference` 或 `previous_inference`。

## 8. 结论层规则
结论层是系统当前处理判断，不是事实。

结论层必须包含：

```text
当前结论
证据等级
引用事实
引用证据
引用推断
主要依据
反证条件
失效条件
复查窗口
动作边界
下一步观察
```

动作边界固定：

```text
SUPPORT / 支持观察 ≠ 买入
PAUSE / 暂停 ≠ 卖出
BLOCK / 阻断 ≠ 确认骗局
RISK_MONITOR / 风险监控 ≠ 确认风险已发生
```

所有结论只作用于 paper / observe / review / handoff，不触发真实交易。

## 9. Handoff 层规则
handoff 是交接包，不是最终结论，也不是交易指令。

handoff 必须说明：

- 下游模块应该读取哪些文件
- 读取顺序是什么
- 哪些字段是事实
- 哪些字段是证据
- 哪些字段是推断
- 哪些字段是结论
- 哪些字段缺失或待复查
- 当前动作边界是什么

## 10. 旧目录治理原则
旧目录默认保留，只读参考。

严格规则：

```text
不移动旧目录。
不删除旧目录。
不覆盖旧文件。
高价值旧数据只能 copy-only 导入。
所有 old_path -> new_path 必须记录。
旧目录只能作为 fallback，不得作为新主写路径。
```

## 11. 读取优先级
Wallet-Intel 读取任务必须按以下顺序：

```text
1. 新标准入口
2. token 索引
3. 数据护照
4. 字段字典
5. 旧路径映射
6. 旧目录只读补查
```

禁止对所有旧目录盲搜。标准入口缺失时，才允许通过旧路径映射进行只读补查。

## 12. 导入后验证原则
导入完成后，不能以文件复制完成作为验收。

必须抽样 3-5 个 token，验证 Hermes 是否能回答：

```text
这个 token 有哪些数据？
哪些是事实？
哪些是证据？
哪些是推断？
哪些是结论？
数据来自旧目录哪里？
后续模块该读取什么？
当前缺什么？
```

只有通过抽样理解验证，才算完成导入。

## 13. 禁止事项
Wallet-Intel Harness V2.0 任务中默认禁止：

```text
不扫描旧数据目录。
不复制旧数据。
不移动旧目录。
不删除旧目录。
不覆盖旧文件。
不修改业务代码。
不触发交易。
不读取或输出私钥、API key、token。
不执行 git push。
不声称完成，除非生成系统写入验证报告。
```

如用户明确进入实际迁移任务，必须另开任务护照并重新授权；本政策本身不授权迁移。

## 14. 恢复规则
若发现以下情况，必须进入 recovery：

- 把推断写成事实
- 把结论写成交易指令
- 旧路径扫描范围失控
- 缺少 old_path -> new_path 追溯
- handoff 包无法说明下游读取
- 导入后验证无法按 token 解释数据
- 未验证规则被写入长期记忆

恢复动作：停止写入、生成 recovery report、回到任务护照和 workflow 阶段，不得继续盲目执行。

## 15. 记忆规则
未验证规则只能写入候选记忆，不得直接写入长期记忆。

可进入长期记忆的条件：

```text
已落地为控制面 / workflow / 模板 / 验证报告；
已通过独立验证；
不是临时任务进度；
不是未经验证的路径猜测。
```
