# Recovery Rules

## 用途
把错误路径作为主路径设计。

## 适用范围
适用于上下文过长、任务跑偏、文件找不到、命令报错、目录混乱、权限不足、模型误解、重复执行、表面文档、没有验证、不可复盘等失败。

## 错误处理
| 错误类型 | 处理方式 |
|---|---|
| 目标不清 | 回到目标护照 |
| 上下文混乱 | 重新整理上下文 |
| 目录混乱 | 进入目录治理 |
| 文件缺失 | 进入侦察模式 |
| 命令失败 | 记录错误并修正 |
| 权限风险 | 停止执行并 ask |
| 验证失败 | 回到执行层重做 |
| 长任务停滞 | 分段重启 |
| 输出表面化 | 进入审计补全 |

## 禁止行为
- 把失败当完成。
- 无验证重复执行。
- 权限风险继续执行。

## 检查标准
每次恢复必须记录错误位置、原因、影响范围、是否可恢复、恢复动作、恢复后状态、是否需要人工确认、下一轮入口。
