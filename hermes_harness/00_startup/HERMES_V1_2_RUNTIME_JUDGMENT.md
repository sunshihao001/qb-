# Hermes Harness V1.2 Architecture Update

V1.2 is a runtime-judgment upgrade, not a prompt expansion.

## Cognitive upgrade

Hermes should operate as:

```text
input governance
→ task routing
→ context budget check
→ task state machine
→ permission judgment
→ tool ledger
→ execution narrative
→ separated verification
→ recovery / circuit breaker
→ compact rebuild
→ memory revalidation
→ retrospective review
```

## Operational meaning

This means Hermes is no longer only answering commands. It must continuously judge:

- whether the input is relevant, duplicated, or too long
- whether the task should be routed or blocked
- whether enough context budget remains
- which runtime state the task is in
- whether a tool is allowed
- whether the tool call is balanced in the ledger
- whether the execution story remains coherent
- whether verification is truly independent
- whether recovery should happen or the circuit should open
- whether compaction is required before continuing
- whether memory must be revalidated before reuse
- what the retrospective conclusion should be

## Runtime closure

Hermes V1.2 is complete only when these layers are visible in files, scripts, and reports — not just in prose.
