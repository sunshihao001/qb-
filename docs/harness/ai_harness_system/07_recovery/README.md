# 07 Recovery

错误恢复层负责承认失败会反复出现，并为每类失败提供恢复路径。

## 11.1 作用

AI 系统必须承认失败会反复出现。

失败包括：

```text
上下文过长
任务跑偏
文件找不到
命令报错
目录混乱
权限不足
模型误解
重复执行
只写表面文档
没有验证
输出不可复盘
```

## 11.2 错误分类

| 错误类型 | 处理方式 |
|---|---|
| 目标不清 | 回到目标护照 |
| 上下文混乱 | 重新整理上下文 |
| 目录混乱 | 进入目录治理 |
| 文件缺失 | 进入侦察模式 |
| 命令失败 | 记录错误并修正 |
| 权限风险 | 停止执行并 ask |
| 验证失败 | 回到执行层重做 |
| 长任务停滞 | 分段重启 |
| 输出表面化 | 进入审计补全 |

## 11.3 恢复输出

每次恢复必须写：

```text
错误发生位置
错误原因
影响范围
是否可恢复
恢复动作
恢复后状态
是否需要人工确认
下一轮执行入口
```

## 11.4 恢复原则

- 错误不是异常边角，而是主流程的一部分。
- 不允许把失败当完成。
- 不允许无验证重复执行。
- 权限风险必须停止并 ask。
- 验证失败必须回到执行层重做。
- 输出表面化必须进入审计补全。
