# Risk Tier Policy

## 用途
将权限从命令清单升级为风险分级策略。

## 权限动作
- ALLOW：默认允许。
- ASK：必须获得用户确认。
- DENY：默认禁止。

## 风险等级

| 风险 | 含义 | 默认 |
|---|---|---|
| R0 | 只读 | ALLOW |
| R1 | 写文档 / 新报告 | ALLOW |
| R2 | 写代码 | ASK |
| R3 | 改配置 | ASK |
| R4 | 删除 / 移动 / 覆盖 | DENY |
| R5 | 外部网络 / 密钥 / 交易 / 生产 | DENY |

## 示例

| 动作 | 风险 | 默认 |
|---|---|---|
| 读取 markdown | R0 | ALLOW |
| 创建新报告 | R1 | ALLOW |
| 修改已有代码 | R2 | ASK |
| 修改配置 | R3 | ASK |
| 删除目录 | R4 | DENY |
| git push | R5 | DENY |
| 读取私钥 | R5 | DENY |

## 禁止行为
- 把 R4/R5 降级为自动执行。
- 以任务紧急为由绕过 ASK。
- 对密钥、私钥、生产交易做默认允许。
