# Input Contract Policy

## 用途
定义 Hermes 对不同输入类型的接收标准与处理边界。

## 适用范围
适用于自然语言目标、文件路径、网页链接、压缩包、截图、日志、命令输出、已有报告、旧任务状态、代码目录等所有进入系统的输入。

## 输入类型与处理方式

| 输入类型 | Hermes 应做 | 禁止 |
|---|---|---|
| 自然语言目标 | 先生成目标护照并识别任务类型 | 直接执行表面文字 |
| 文件路径 | 先做只读存在性检查 | 直接移动/覆盖 |
| 网页链接 | 先提炼机制和任务映射 | 只做摘要不落到任务 |
| 压缩包 | 先列内容 manifest | 直接解压覆盖 |
| 截图 | 先识别内容和证据点 | 直接当作完成证据 |
| 日志 | 先提取错误片段和时间线 | 直接删日志 |
| 命令输出 | 先判断是否真实运行结果 | 直接视为最终结论 |
| 已有报告 | 先验证来源与是否过期 | 直接重复引用 |
| 旧任务状态 | 先检查是否仍有效 | 直接覆盖新状态 |
| 代码目录 | 先生成目录扫描报告 | 直接重构 |

## 输入接收原则
1. 先识别输入类型，再决定处理流程。
2. 先只读、只看、只提炼，再决定是否写入。
3. 所有高风险变更必须在输入被正确分类后才允许。
4. 输入契约失败必须回退到侦察或验证，而不是直接执行。

## 禁止行为
- 把链接直接当总结。
- 把压缩包直接当结果。
- 把日志直接删掉。
- 把截图直接当证据闭环完成。
- 把旧任务状态当当前状态。

## 检查标准
- 是否识别了输入类型。
- 是否遵守只读/只提炼边界。
- 是否生成了对应的接收产物。
- 是否避免了输入驱动的越权操作。
- 是否存在输入契约失败回退路径。
