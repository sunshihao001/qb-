# Task Routing Policy

## 用途
定义 Hermes 在接到任务后，如何先识别任务类型，再路由到正确的专业流程。

## 适用范围
适用于所有进入 Hermes 的自然语言目标、文档任务、目录治理任务、代码任务、调试任务、长任务和记忆整理任务。

## 自然语言隐式路由

用户不输入 slash command 时，也必须先路由。自然语言默认先经过：

```text
自然语言输入 → 轻量目标护照 → task_type 识别 → 控制面检查 → 执行/澄清/恢复
```

自然语言与显式命令的等价关系：

| 自然语言含义 | 隐式命令 | task_type |
|---|---|---|
| 模块成熟化/功能是否形成子模块 | `/HER_SYSTEM_DESIGN` + `/模块成熟度扫描` | `module_maturity_governance` |
| 分析长文档/链接/上面的内容 | `/方法轮执行` | `method_wheel` |
| 补全/完善一个系统 | `/任务拆解` + `/执行一轮` | `system_design` / `controlled_execution` |
| 哪些文档缺东西 | `/系统侦察` + `/目录检查` | `directory_governance` |
| 按 HER 底层设置 | `/目标登记` + `/任务拆解` | `control_plane_update` |
| 为什么没按规则执行 | `/错误恢复` | `debug_recovery` |
| 验证是否完成 | `/验证结果` | `verification` |

## 任务类型路由

| 任务类型 | 应走流程 | 关键验证 |
|---|---|---|
| 模块成熟度治理 | 模块成熟度扫描流 | 是否区分 L1/L2/L3、是否给出子模块 promotion 优先级 |
| 文档研究 | 方法轮 | 是否提炼机制、缺口、任务包 |
| 目录治理 | 目录侦察流 | 是否不删除旧数据、是否有映射表 |
| 代码修改 | 工程执行流 | 是否测试、是否 diff、是否可回滚 |
| 系统设计 | 架构设计流 | 是否有边界、模块、验收 |
| 调试恢复 | 错误诊断流 | 是否定位原因、是否生成恢复报告 |
| 长时间任务 | 分段循环流 | 是否每轮有状态、日志、续跑入口 |
| 记忆整理 | 记忆审计流 | 是否 verified、是否无污染 |

## 路由原则
1. 先分类，再执行。
2. 不能所有任务都走同一条通用流程。
3. 路由结果必须写入目标护照或任务计划。
4. 路由错误必须进入 recovery 并重路由。

## 禁止行为
- 把代码任务当文档任务处理。
- 把目录治理当普通写文件处理。
- 把调试恢复当一般执行任务处理。
- 把记忆整理当普通报告处理。

## 检查标准
- 是否识别任务类型。
- 是否选择了对应流程。
- 是否生成了对应验证标准。
- 是否写入了路由结果。
- 是否存在错误路由回退路径。
