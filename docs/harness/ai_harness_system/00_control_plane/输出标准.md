# 输出标准

控制面规定所有任务输出必须满足的标准。

## 基本要求
- 输出必须对应明确任务类型。
- 输出必须标明所属阶段。
- 输出必须能被验证。
- 输出必须能回流到 repo。
- 输出不能只是一段解释文字。

## 输出原则
1. 先给结论，再给依据。
2. 先给结构，再给展开。
3. 先给可验证项，再给主观判断。
4. 事实、推断、审计、模板不得混写。
5. 不能把未验证内容当最终结果。

## 最低输出元素
- 当前任务类型
- 当前所属阶段
- 输入来源
- 输出目标目录
- 关键约束
- 验证方法
- 回流位置

## 特别约束
- 高风险动作不允许“口头完成”。
- 长任务必须分阶段输出。
- 无法验证时必须明确写出缺口，而不是编造。
