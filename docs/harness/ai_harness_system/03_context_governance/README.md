# 03 Context Governance

上下文治理层负责管理 AI 能看见什么、记住什么、引用什么，以及哪些信息不能进入长期规则。

## 7.1 核心问题

当前很多系统混乱，本质不是 AI 不聪明，而是：

```text
上下文没有分层
记忆没有边界
任务历史没有结构
目录没有语义
文件没有阶段归属
AI 不知道哪些是长期规则，哪些是临时指令
```

所以必须建立上下文治理层。

## 7.2 上下文分层

| 上下文类型 | 保存内容 | 是否长期保留 |
|---|---|---|
| 系统宪法 | 不变规则、边界、方法论 | 长期 |
| 项目记忆 | 当前项目目标、目录、模块 | 长期 |
| 任务记忆 | 当前任务进度、阶段状态 | 中期 |
| 会话记忆 | 本次对话发生的内容 | 短期 |
| 证据上下文 | 文件、截图、报告、日志 | 按任务保留 |
| 执行上下文 | 命令、输出、错误、测试结果 | 按运行保留 |
| 复盘上下文 | 失败原因、修正方案、经验 | 长期精选 |

## 7.3 记忆写入规则

```text
不能把所有聊天都写入记忆。
不能把临时想法写成长期规则。
不能把失败结论当成最终事实。
不能把未验证内容写进系统宪法。
不能把过期文件路径当作长期路径。
```

## 7.4 正确写入方式

```text
记忆条目/
├── 记忆标题
├── 记忆类型：系统规则 / 项目事实 / 任务状态 / 失败经验
├── 来源
├── 适用范围
├── 有效时间
├── 是否已验证
├── 是否可覆盖
└── 下一次调用方式
```

## 7.5 治理原则

- 先分层，再写入。
- 先验证，再长期保存。
- 当前会话不是长期记忆。
- 任务状态不是系统宪法。
- 证据上下文必须能追溯来源。
- 复盘经验必须经过筛选，不能原样沉淀所有失败内容。

## 12.1 记忆沉淀层作用

记忆沉淀层负责把一次任务中的有效认知沉淀为以后可复用的系统资产。

## 12.2 记忆类型

```text
系统规则记忆
项目结构记忆
目录标准记忆
命令使用记忆
失败案例记忆
验证标准记忆
方法轮记忆
Bot 协作记忆
```

## 12.3 记忆不能写什么

```text
未验证猜测
一次性临时路径
错误命令
过期状态
重复废话
没有来源的结论
```

## 12.4 记忆写入格式

```text
记忆名称：
记忆类别：
适用系统：
来源任务：
核心内容：
证据文件：
验证状态：
下次调用方式：
失效条件：
```
