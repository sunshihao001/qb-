# 01 Goals

目标接收层负责把用户的自然语言目标变成结构化任务。

## 5.1 作用

用户通常会用自然语言描述目标，例如：

- 我要做一个专业系统
- 我要让 HER 理解我的意思
- 我要建立目录标准
- 我要让 Bot 协作
- 我要把方法轮落地
- 我要做长时间任务

AI 不能直接按表面文字执行，必须先做目标解析。

## 5.2 目标护照

每个任务进入系统后，必须先生成一个目标护照。

```text
目标护照/
├── 原始用户目标
├── 真实意图
├── 任务类型
├── 涉及系统
├── 预期产物
├── 风险边界
├── 是否需要工具
├── 是否需要长任务
├── 是否需要验证
└── 下一步路线
```

目标护照是任务的第一份结构化记录，后续所有计划、执行、验证、恢复都应参考它。

## 5.3 任务类型分类

| 类型 | 判断标准 | 处理方式 |
|---|---|---|
| 研究型 | 需要理解文章、书、资料 | 进入方法轮 |
| 系统设计型 | 需要构建架构 | 进入体系设计 |
| 工程落地型 | 需要改文件、跑命令 | 进入 Hermes 任务包 |
| 调试型 | 系统没反应、报错、失效 | 进入错误诊断 |
| 标准化型 | 目录混乱、字段混乱、流程混乱 | 进入治理层 |
| 复盘型 | 判断之前做得是否有效 | 进入审计层 |

## 5.4 任务分流原则

- 先判断任务类型，再决定进入哪一层。
- 不允许把所有请求都当成工程落地任务。
- 不允许把系统设计问题直接当普通文本回复。
- 不允许跳过目标解析直接执行。

## 5.5 输出要求

目标接收层至少要输出：
- 原始用户目标
- 真实意图
- 任务类型
- 涉及系统
- 预期产物
- 风险边界
- 下一步路线
