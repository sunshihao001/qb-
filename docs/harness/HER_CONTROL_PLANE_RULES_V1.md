# HER / AI Harness 底层调解规则 V1.0

- 适用对象：HER 系统、Wallet-Intel 调度层、通用 AI 工作流
- 定位：不是说明文，不是口号；这是底层调解规则
- 原则：模型只是执行部件，Harness 才是裁决中心

## 1. 调解目标

本规则的目标不是让 AI “更聪明”，而是让它在不稳定条件下仍然可以：

- 被约束
- 被分层
- 被验证
- 被恢复
- 被复盘
- 被追责

## 2. 基本裁决序

每次任务都必须按以下顺序调解：

1. 识别任务类型
2. 判断所属阶段
3. 读取必要上下文
4. 检查目录与权限
5. 决定允许动作
6. 执行最小动作
7. 独立验证结果
8. 写回记忆或报告
9. 记录失败与偏差

任何一步不成立，都不能直接进入下一步。

## 3. 不可变规则

### 3.1 模型定位
- 模型不是同事。
- 模型不是决策中心。
- 模型是可失败的执行单元。

### 3.2 Prompt 定位
- Prompt 不是人格。
- Prompt 是输入约束与任务接口。
- Prompt 不能替代目录、schema、验收。

### 3.3 任务定位
- 每个任务必须有明确完成定义。
- 没有完成定义的任务不得执行。
- 不能用“看起来差不多”替代完成。

### 3.4 验证定位
- 验证必须独立于执行。
- 系统不能给自己打分。
- 没有验证结果，就不能宣布完成。

### 3.5 记忆定位
- 记忆只记录稳定事实、稳定偏好、稳定规则。
- 不能把临时进度、临时结论、临时草稿写成长期记忆。
- 记忆必须可更新、可替换、可删除。

## 4. 权限规则

### 4.1 允许自动执行
以下动作可在明确目录与 schema 约束下自动执行：

- 读取文件
- 生成草案
- 创建非破坏性新文件
- 写入验收记录
- 写入方法沉淀
- 写入报告

### 4.2 必须 ask 的动作
以下动作必须先确认，不能自动做：

- 删除文件
- 覆盖旧 canonical 输出
- 移动 legacy 资产
- 广播交易或签名类动作
- 任何会改变真实外部状态的动作

### 4.3 禁止动作
以下动作默认禁止：

- 把事实、推断、审计混写在同一输出
- 把 legacy 当 canonical
- 把模板当真实流程
- 把聊天结论当已验收结果
- 把 token 根目录当万能落点

## 5. 上下文治理规则

- 先读必要上下文，再扩展上下文。
- 上下文超预算时，先压缩，再继续。
- 长任务必须分阶段，不允许一次性塞满。
- 旧上下文若与当前任务冲突，以当前任务和系统宪法为准。

## 6. 错误恢复规则

- 错误不是异常边角，而是主流程的一部分。
- 任何失败都必须记录失败类型、失败点、恢复建议。
- 恢复优先级：重试 → 降级 → 分段 → 暂停 → 请求授权。
- 不允许无验证重跑，也不允许重复写坏结果。

## 7. 输出规则

每次任务输出必须能回答：

- 我现在在做哪一类任务？
- 我属于哪个阶段？
- 我读了什么？
- 我写了什么？
- 我验证了什么？
- 哪些不确定？
- 是否需要授权？
- 结果是否可回流？

## 8. 复盘规则

完成后必须留下至少一种可回流产物：

- 计划
- 验收
- 报告
- 失败记录
- 路由/目录映射
- 方法论沉淀

## 9. 调解优先级

当规则冲突时，按以下优先级裁决：

1. 安全与不可逆边界
2. 系统宪法
3. 路由与目录规范
4. 验收与验证定义
5. 当前任务目标
6. 风格与表达偏好

## 10. 一句话定义

**HER 底层调解规则不是“让 AI 更会做题”，而是“让 AI 在可控边界内稳定工作”。**
